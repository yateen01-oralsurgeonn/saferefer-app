# SECURITY: SafeRefer design review (16 Nov 2026)

Scope: the design in PLAN.md and PROMPTS.md. No app code exists yet. Repo history was not scanned; the T13 list below does that.
Severity: H = an identifier or secret can leave the browser. M = needs a second failure first. L = hygiene.
Rows: A = identifier reaches the cloud. B = token map leaks. C = secrets and debug tokens. D = Nano fails mid-redaction.

| # | Risk | Sev | Fix | Task |
|---|---|---|---|---|
| A1 | Nano silently misses a name. The send guard only knows map values, so the note passes | H | Keep the Approve gate and amber underline; publish the miss rate; README says the dentist's check is the real control | T4, T5, T8 |

It does throw and send nothing when `LanguageModel` exists but `availability()` is `unavailable` (tested in a fresh Chrome profile) | H | The app, not the SDK, is the lock. Before every redaction call: `typeof LanguageModel !== 'undefined'` and `await LanguageModel.availability() === 'available'`, else go to manual mode with no network call. Keep `ONLY_ON_DEVICE` as a second lock. Unit test with `LanguageModel` undefined asserts zero `fetch` calls. Also guard the dev "on-device only" test mode on the setup page. App Check timing, tested 18 Nov (Playwright, fresh Chrome profile, App Check cache cleared): `exchangeDebugToken` fires **at page load (58 ms)**, before any Ask, and pressing Ask in on-device-only mode adds **no** request. It carries the debug token, not note text. So "zero requests when Ask is pressed" is literally true; say "no request containing note text" for the page as a whole, since load makes App Check and reCAPTCHA calls | T1 (tested), T4 (guard) |
